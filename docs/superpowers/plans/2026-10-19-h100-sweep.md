one-epoch trials on a fixed 1,000,000-example training subset. Compare 10+10 and
12+8, both d1024/FFN4096/BPE8000, with LR 1e-4 and 2e-4. Every trial starts from
scratch, never from the current model checkpoint. Global batch stays 256.

1. Complete SDPA batch128x2 versus batch256x1 speed and memory checks. Keep the
   fastest configuration with acceptable memory headroom. Attention comparison

2. Preserve checkpoint-15000 with optimizer, scheduler and RNG; stop the old run
   only after its on-save layout marker. Store a ready resume command.
3. Reuse the existing filtered tokenized cache. Save fixed random train indices
   (1M) and validation indices (20K), seed 42, never use either test split. All
   trials reuse this prepared subset, same data ordering and initialization seed.
4. Implement a standalone sequential sweep runner with isolated output dirs,
   finite-loss checks, resume/skip completed trials, per-trial logs and a summary
   ranked by final token-weighted validation loss after exactly one epoch.
   Use existing Trainer metric, FP32 CE and deterministic grouped sampler.
5. Test grid/data selection and output protections, run a small GPU Trainer smoke
   test, review, launch four trials in tmux and verify the first trial progresses.
   Report that short-run rankings need longer confirmation before a full run.

Defaults: BF16, fused AdamW, SDPA, torch.compile dynamic, warmup5% then cosine,
weight decay .01, clipping1, validation every1000steps and at end, no early
stopping for this equal-budget screen, 4 dataloader workers. One process per
trial frees GPU allocations between trials. Save one final full checkpoint.
